# App UI internals — `data/app-template.html`

Maintainer reference for the offline study app. Read this **only when editing `data/app-template.html`**
(it is not auto-loaded — CLAUDE.md keeps just a pointer here). To change the app UI/logic edit
`data/app-template.html` (keep the `/*__BANK__*/[]` and `/*__HISTORY__*/{}` placeholders valid as empty
literals); to change the data it receives edit `data/app-build.md`. Baseline: v0.6.3+.

## Copy register (applies to EVERY string a learner reads)
Same rule as `data/teaching-method.md` **Rule 0b**: a 12-year-old should follow every sentence that is not
a technical term. When you add or edit UI copy in this file, hold it to that:

- One idea per sentence, active voice, everyday words. Split anything that needs a second read.
- **No em dashes in prose.** Use a full stop, a comma, a colon or brackets. ` · ` stays as a compact
  separator in dense labels (`accuracy · coverage · blueprint weight`), which is typography, not prose.
- Exam vocabulary keeps its exact form: `stop_reason`, `tool_choice`, `PreToolUse`, *winning condition*,
  *axis*, *near-miss*, plus every flag, field and file name. Simplify the sentence, never the term.
- **Never rewrite bank content.** Question stems, options and `q.explanation` render straight from `BANK`
  and are exam artefacts. The same goes for `AXIS_INFO.triggers` chips, which are stem trigger phrases.
- `AXIS_INFO.triggers` is data, not prose: `axisTriggers()` splits the chips from the trailing note on
  `" — "`, so that one em dash must stay.
- **Dates: one canonical display format, day-first and dot-separated, via `fmtDate(ts, style)`.** Storage
  stays ISO (`YYYY-MM-DD…`) so it sorts; **every date a learner SEES goes through `fmtDate`** — never a raw
  ISO slice. Three styles: **`full` → `dd.mm.yyyy`** (default; exam-history rows, chart tooltips), **`short`
  → `dd.mm.yy`** (compact meta, e.g. the Weaknesses per-question `Exam #N · dd.mm.yy`), **`md` → `dd.mm`**
  (chart x-axis ticks, no year, no trailing dot). Trend charts group the x-axis by DATE via `dateScale()`:
  every SITTING gets the same horizontal step; each calendar date owns one cell sized to its sitting count
  (and ONE `md` label centred on it), so same-day exams sit one step apart and never share or overlap a
  label. When you add a new date display, call `fmtDate` — do not reintroduce
  `slice(0,10)`/`slice(5,10)` for display.

- **Discard unrecorded sittings** (`discardPending()`): the dashboard pending banner has a **Discard** button beside **Copy unrecorded** that clears `LS_PENDING` (finished-but-unrecorded sittings held only in `localStorage`) after a confirm. Needed because `localStorage` is keyed to the `file://` origin, so it survives deletion of `~/.claude/ccaf-progress/` and a rebuild to the same path — Discard is the in-UI way to drop stale local sittings. Recorded progress in `stats.json` is untouched.
- **Results review** (`renderResults` → `renderReviewList()` + `reviewState`): opens **misses-only** by default; a segmented `[Misses only | All]` toggle and per-domain filter chips (only the domains present in that exam) re-render the list in place without leaving the view. Empty states: "No misses. Nice." vs "No questions match this filter." Each review card shows an **axis badge** (`Axis N · <name>`) from `q.axis`. Score hero / per-domain / export are untouched.
- **Dashboard 5-axis tally** (`computeAxisTally(merged)`): computed **client-side** from `BANK[id].axis` over the user's misses (latest attempt wrong); `HISTORY.axis_tally` is only a fallback when the bank has no axis data.
- **Dashboard section order** (`renderDashboard`): Exam readiness hero → **Learning progress** → **Exam history** → **By domain** → 5-axis tally → …
- **Dashboard "By domain"** (per-domain block in `renderDashboard` + `taskLabelMap()` + `taskStats(d, merged)`): one collapsible `<details class="dom-card">` per domain, **all collapsed by default**. The always-visible `summary.dom-sum` shows the colored dot, `D# <name>`, `NN% accuracy`, `NN misses`, and a `focus` flag. Expanded, three separately-labelled `.dom-tile` (`.statcard`) metrics — **Accuracy** (`perDom.correct/seen`, `.mini-arc`), **Coverage** (`uniqByDom/counts`, `.meter`, the "questions seen" quantity), **Exam weight** (`BLUEPRINT[d]%`, stated as a fixed constant) — then the per-domain **error-trend sparkline** (`domErrTrend(d, allExams)`, see below), then a **"By task statement"** grid of small `.ts-card`s: ONE card per `<d>.<n>` present in the bank for the domain (label from `taskLabelMap()`, read off the Reference section titles), each showing a coverage meter + `A/T answered` (distinct questions seen of that task's `T` bank questions) and `F failed` (distinct ever-wrong, `wrong>0`, warn-tinted; "none failed" when 0), from `taskStats(d, merged)` over `mergedAnswered()`. This replaced the earlier "Where you slip" bar/grid renders (an accuracy+weight+coverage overlaid bar, then a proportional bar, then a miss dot-grid); the per-exam miss detail now lives in the error-trend dot tooltip instead. No new injection — counts from `merged`, and `<d>.<n>` labels from `taskLabelMap()` which SPLITS them off the bundled Reference section titles. Known limitation: the dashboard's `taskLabelMap()` still reads its `<d>.<n>` labels off the bundled Reference section titles, so if reference curation ever lags the bank a task shows a bare number (the render suppresses the "1.1 1.1" duplicate). Since 0.19.0 the canonical `task-statements.json` labels ARE injected — as `HISTORY.task_labels` → the `TASK_LABELS` global (folded into `HISTORY`, NOT a fourth placeholder) — and the Weaknesses card header reads them directly; `taskLabelMap()` could switch to `TASK_LABELS` to close this gap.
- **Score-trend sparkline** (`renderTrend(allExams)` + `examPct`) — the ONLY content of the Exam-history section now (**the old per-exam list `.exlist` was removed**; every sitting's detail lives in the dot tooltip). Self-contained inline SVG. Mock sittings = connected line + dots (with the score above each) + angled `dd.mm` date labels; external results = separate diamond markers, **never averaged in**; a dashed pass line at `PASS_PCT`, labelled "NN% pass line" at the far left — an HTML `.trend-passlbl` pinned over the plot (top = `passY/H` %, so it holds at any render scale) rather than SVG text, so it stays visible when the chart scrolls; the data keeps its own left lane (`LX` inset) so at scroll position 0 no marker sits under it. Legend = Mock + External only (no pass-line entry). Each marker is a `.dt-dot` with the **same rich tooltip** as the domain charts (shared `.domtip`/`DOMTIP`, key `s-<exam_id>`): header `dd.mm.yyyy · N% score`, a **meta line** folding in the old list row (`Type · mode/label · correct/total · N misses · time · over-time`), then the **all-domain error breakdown** (per domain: `wrong/total` for a mock from `per_domain`, or `N%` for an external from `per_domain_pct`, with a "shown separately" footer). Degrades to a "not enough data" note when <2 mock sittings. viewBox 1000×230 base (1 unit ≈ 1px) so type/marks stay crisp — **width grows with the sittings** (see "Trend-chart sizing" below).
- **Domain error trend** (`domErrTrend(d, allExams)`): a compact inline-SVG sparkline **inside each domain's `.dom-card`** (one per domain, revealed when the card expands — NOT a single standalone multi-line chart). Plots that ONE domain's **% wrong** across the MOCK timeline (`errPct = 100*(total-correct)/total` from each sitting's `per_domain[d]`; higher = worse, external excluded), colored `DOMAIN_VAR[d]`, with 0/50/100% gridlines and angled `dd.mm` x-axis date labels under each date (end-anchored, `rotate(-28)`, thinned from the real plot width via `trendTickStep()`; `padL` leaves room so the first label never clips; `.dt-svg` keeps `overflow:visible`). The viewBox is 1000×150 base (1 unit ≈ 1px) and grows with the sittings (see "Trend-chart sizing" below) so text/dots/strokes render at a normal, crisp size instead of ballooning when a tiny viewBox is stretched to full width. `<2` mock sittings with that domain → a short "not enough mock exams" note. Each dot (`.dt-dot`, keyboard-focusable) has a **rich hover/focus tooltip** (`.domtip`, one shared floating element, delegated listeners that survive dashboard re-renders; content from the module-level `DOMTIP` map keyed `d-examId`): a header `date · N% wrong` then a list of the task statements missed in THAT exam with a per-task miss count (`<d>.<n> <label> — N`), or "No misses this exam". This is where the per-exam miss detail lives now that the miss grid is gone. Shows how each domain trends over time next to its own metrics (pairs with the dynamic focus below).
- **Dynamic focus** (`build-app.py` `recent_focus()`): `HISTORY.focus_domains` is now computed from the **last ≤5 mock sittings** by per-domain error RATE (top 2), so focus tracks recent slips. Fallbacks when no mock data: `profile.md` `## Focus domains`, then lowest-accuracy-over-all, then `[]`. The app reads `focus_domains` as before (coach "Focus next", which By-domain `.dom-card` opens by default, config chips, weak-mode weight) — the shape stays `list[int]`.
- **Weak-mode spaced-repetition** (`selectSet` weak branch): a `due` term ranks unseen / long-unseen questions higher (`min(1.5, ageDays/14)`, unseen = full 1.5), on top of the missed/unseen/domain-weakness/focus/blueprint terms. Depends on `answered[id].last_ts` injected by `app-build.md` (ISO ts of the most recent attempt).
- **Exam is one-question-per-screen** (`renderExam` → `renderCurrentQuestion()`, `examStage` = `"question"|"review"`): only the current question's `.q` card is in the DOM (mirrors the real proctored exam; no scroll-spy — the old `IntersectionObserver` was removed). `currentQId` is the single source of truth (keyboard answers can no longer hit the wrong question). Navigation: **Prev / Next** buttons in the card footer (last question's Next = **Review & submit**), the `.navgrid` chips (real `<button>`s, `gotoQ(i)`), a **Jump to unanswered** header button, and keys `1–4`/`A–D` = pick, `J/K`/`←→↑↓` = move, `F` = flag. `gotoQ` re-renders the single card + persists + scrolls to top. `pickAnswer(id,L)` is the shared select path.
- **Mark for review + review-before-submit gate** (`toggleFlag()`, `exam.flagged`, `showReviewScreen()`): a per-question flag (persisted, shown as a warn dot on the navchip). Submit (header button or last Next) opens `showReviewScreen()` — lists unanswered + flagged as clickable jump chips — instead of a bare `confirm`; its **Submit exam** calls `submitExam()`. Header **Quit** (`quitExam()`) leaves without submitting: persists in-progress, restores the dashboard resume banner.
- **Navchip states disambiguated**: answered = solid neutral `--ink2` (was `--accent`), current = accent ring, flagged = warn dot — so "answered" and "current" no longer share the accent hue.
- **Accessibility pass**: global `:focus-visible` / `.opt:focus-within` outlines; `@media (prefers-reduced-motion:reduce)` + `scrollTopSmooth()` gate all smooth-scroll/animation; navchips are real buttons with `aria-label` state; `showView()` moves focus to the view heading and announces via the `#srStatus` `aria-live` region (exam view manages its own focus in `renderCurrentQuestion`); export `<textarea>` is labelled.
- **Optional time limit — 2 min/question, never auto-submits** (`cfg.timed` → `exam.limit_seconds = count*120`; `updateClock()`, `showTimeUp()`/`hideTimeUp()`, `exam.over_time`): a **Time limit** field on New exam (`No limit` / `Timed · 2 min/question`). When timed, the header clock counts **down** (red-pulse `.clock.low` in the last minute); at zero it does **NOT** submit — it sets `exam.over_time=true`, shows the non-blocking `#timeUpBanner`, and the clock flips to counting **up** in steady red `.clock.over` (`+MM:SS`). This is practice: the learner always finishes every question and submits manually through the normal review gate. `grade()` writes `over_time` + `limit_seconds` into the result JSON; `/ccaf:result` copies them onto the `exam_history` entry; results header and dashboard history show an "⏳ over time" marker (score unaffected). `limit_seconds`/`over_time` persist in `localStorage` and restore on resume-later. Untimed = `0` (clock counts up, no banner).
- **Mock modes** (`renderConfig()` `MODES`, `poolFor`/`availByMode`/`selectSet`): `weak` / `unseen` / `random` / `review` (latest-attempt wrong) / **`failed`** ("Ever failed" — missed at least once EVER even if passed since; a superset of `review`). Membership = `m.wrong>0 || m.last_correct===false` (the `last_correct` clause keeps legacy compact records — `attempts:<int>`, no per-attempt counts, `right=wrong=0` — from being silently dropped). `failed`/`review` both draw by shuffle (no ordering); an empty `failed` pool shows the same "no missed questions yet" note as `review`.
- **Per-question attempt data** (`build-app.py` `answered` loop): each `HISTORY.answered[id]` carries `right` + `wrong` (counts over `attempts[].correct`; `0/0` for compact/legacy int-shaped records), a `misses` list (wrong attempts as `{exam_id,ts}`), and **`log`** = the FULL per-attempt timeline `{exam_id, correct, ts}` (both right AND wrong, chronological). `log` is the canonical list; `misses`/`right`/`wrong` are derived summaries kept for the trend tooltip + `failed` mock mode. `mergedAnswered()` folds `pending` attempts into `right/wrong`. Powers the `failed` mock mode and the Weaknesses per-question **Answer stats** panel (see below).
- **Learning-progress card + malformed handling** (`lpAnyActivity()`, `learningDomain()`, `LEARNING_UNREADABLE`): the dashboard renders a "Learning progress" card + per-axis "Tutor recognition" lines from `HISTORY.learning`, gated so it shows nothing when there's no activity. If `HISTORY.learning_unreadable` is true (progress file present but malformed), a warning banner is shown instead of silently rendering zero. See also `app-build.md` `load_learning()`.
- **Cheatsheet tab "Show" filter** (`renderReference()`, `refState.show`, chips `[data-ref-show]`): `Everything` (default, the whole bundled reference) · `My misses · all exams` (rows tied to any question I ever failed) · one chip per mock sitting (`#N · dd.mm`, count of rows). The tie is each row's hand-picked **`q_ids`** ∩ the questions failed (`missExamIds(qid)` over `BANK`, i.e. `answered[].log` + local pending) — so `q_ids` are no longer audit-only; a row with `q_ids: []` never shows under a misses/exam chip. Filtered rows carry a `.ref-hit` badge `N missed` (how many of my failed questions that row answers). Chip counts are over rows passing domain + search (a chip never yields an empty list); a selected exam that drops out resets to `Everything`; the row is hidden when I have no misses at all. Shares `examOrdinals()`, `sortExamIdsNewest()`, `examChipLabel()` with the Weaknesses exam filter.
- **Weaknesses tab** (`renderWeakness()`, tab label "Weaknesses") — the single miss-driven view; it **replaces the former separate "Failed Questions" + "Failed Topics" tabs**. Reads `HISTORY.cheatsheet.entries` (written by `/ccaf:result` + `/ccaf:fail-analysis`, injected read-only by `app-build.md` `load_cheatsheet()`) through the shared `cheatList()`, which **sorts entries by `lastMissTs(qid)` descending — most recently MISSED first** (the ts of the newest WRONG attempt in `HISTORY.answered[qid].log` + local `pending`, via the shared `wkAttempts(qid)`; fallback `last_ts`/`first_ts` only for an entry with no attempt data). NOT the entry's `last_ts`: `/ccaf:result` bumps `last_ts` on a correct answer too (`status:"mastered"`), so it means "last touched" and would float a question just answered RIGHT to the top. Per-answer time: since 0.19.5 `pickAnswer` stamps `exam.answered_at[id]` (last pick wins; persisted in `LS_INPROGRESS`, restored by `resumeExam`) and `grade()` emits it as `answers[].answered_at`; `/ccaf:result` writes it into `attempts[].ts`, so same-sitting misses order by when they happened (sittings recorded before 0.19.5 keep the sitting's `ts` for every attempt — stable but arbitrary order inside that exam). `wkAttempts` uses `answered_at||p.ts` for local pending sittings too. **Exam filter**: a second chip row (`[data-cs-exam]`, `cheatState.exam`, label `Exam`) — `All exams` + one chip per mock sitting in which any of the domain/search-filtered questions was FAILED (`missExamIds(qid)` = exam_ids of wrong attempts), newest first (`examOrdinals()` now carries `ts`), labelled `#N · dd.mm` with a `.cs-cnt` count of failed questions; an unrecorded pending sitting labels `Unrecorded · dd.mm`. Built from the domain+search-filtered set so a chip never yields an empty list; a selected exam that drops out of the set resets to `all`; the row is hidden when only one exam qualifies. `HISTORY.cheatsheet_unreadable` → `.banner.warn`. Structure: **one card per topic** (`<article class="cs-card cs-compact">`), grouped by `topicKey(e)` (uses `e.topic`, else the note's first `## ` heading, else `q<qid>` so a note-less entry still gets its own card and is never dropped); newest topic on top. The card is a **stack of collapsibles, all closed by default**, and its left rail + header/label accents are the **domain colour** — `--dc` set inline on the `<article>` from `DOMAIN_VAR[domain]` (the same domain-coloured treatment-B header language is used by the Cheatsheet/Reference tab's `.ref-dom-h`/`.ref-sec-h`). Card order:
  1. **Header** (`.wk-head`, treatment B): a domain-coloured kicker `Domain <d> · <short name>` (`DOMAIN_SHORT`) over a big title `<n.n> <task label>`. The label is the CANONICAL one from `TASK_LABELS` (= `HISTORY.task_labels`, injected by `build-app.py` from `task-statements.json`), rendered via `rich()` so a `` `token` `` in it becomes a domain-coloured mono word (`.wk-title code`, no box); falls back to the number, then the domain name. The domain lives ONLY on this header — never on the individual questions.
  2. **Тема block** (`<details class="wk-topic">`, present only when there's a note/topic): the summary reads **`Topic: <title>`** (the localized `Topic` label — domain-coloured — plus the note's first `## ` heading, else `e.topic`); the body is `mdBlock(noteBody)` = the note WITHOUT that first heading, so the title isn't shown twice.
  3. **`.wk-qlabel`** = **`Failed questions · N`** (localized), then EVERY entry in the group as its OWN **collapsed `<details class="wk-q">`** via `wkQuestion(e, ords)` — flat siblings, each independently expandable.
  Each `wkQuestion` **summary IS the question**: `BANK[qid].stem` (via `rich()`) inside `.wk-stem`, clamped to two lines (`-webkit-line-clamp:2`) when closed and **un-clamped to the full stem when open** — no repeated question, no stats in the summary (falls back to the decision headline if the qid isn't in the bank). **Body:** the options first (`wkOptions`, correct = green `.cs-o-correct`, the learner's `your_pick` = **red** `.cs-o-pick` + a localized `your pick` tag), then the **`Breakdown`** panel (`.wk-p-b`: `rule` → the three beats signal / answer / flip via `cheatBeat`, with the axis badge `.wk-axis` in the panel header), then the **`Answer stats`** panel (`.wk-p-s`: `wkStatsPanel(tl)` — a `✗n · ✓n` summary + one `✓/✗ · Exam #N · date` row per attempt). `status:"mastered"` entries render inside their topic with the green `mastered` styling. Filters: domain chips + a search box (search covers `note`/`task` + the five fields); the **axis filter was dropped** (topic-centric view). `cheatState` stays `{domain, axis, q}` with `axis` unused. (The former `wkDots`/`wkLast`/`wkHistory`/`cheatScenario` and the older `cheatCard()`/`examMetaLine()` were removed — do not reintroduce.)
  - **Exam ordinal + date:** `examOrdinals()` assigns a chronological `n` (1..N over `HISTORY.exam_history` mock sittings sorted by `ts`). `wkTimeline(qid, ords)` builds the full attempt timeline from `answered[<qid>].log` (`{exam_id, correct, ts}`, injected by `build-app.py`) plus any local `pending` attempts, sorts chronologically, and maps each attempt to its `{n, date}` via `ords`; `examLbl()` formats `Exam #N · date`. This feeds the **`Answer stats`** panel (`wkStatsPanel`). Fallback when an entry has no `log` (legacy build): rows derived from `.misses`; an attempt whose `exam_id` isn't a recorded mock (pending/external) shows its `ts` date with no ordinal ("Exam · date").
  - **`mdBlock`** renders a tiny markdown subset for the note: `## ` → `<h4 class="cs-c-h">`, `- ` → `<li>`, a `- [you] ` bullet → `<li class="cs-c-hit">…<span class="cs-c-hit-b">${t("your pick")}</span></li>` (the trap the learner fell for, from `your_pick`; the tag is localized), blank-line-separated plain lines → `<p class="cs-c-p">`, all inline text through `rich()`. No other markdown. The old `Detailed`/`Compact` toggle, `cheatState.mode`, `renderCheatCompact`, `cheatCompactMeta`, `data-cs-mode`, and the former `renderCheatsheet`/`renderTopics` (+ their `#view-cheatsheet`/`#view-topics` containers) were **removed** — do not reintroduce them.
  - Authored-field language: `learning_language` (per `/ccaf:result` / `/ccaf:fail-analysis`); exam terms, quotes and API tokens stay English. No localized copy, no cross-language fallback — the stored fields carry the language.
  - **Chrome-label i18n (the ONLY localized chrome — Invariant #8 carve-out):** the eight Weaknesses content-labels that sit on that localized prose (`Topic`, `Failed questions`, `Breakdown`, `What gave it away`, `So the answer is`, `Your instinct, and when it is right`, `your pick`, `Answer stats`) render through `t()` against the template's `UI_I18N` table, keyed by `LANG = HISTORY.learning_language` (injected by `build-app.py` from `settings.json`, default `"English"`). Any language not in `UI_I18N` falls back to English per key (free-form-language safe). Add a language = one `UI_I18N` block with the same keys; localize another label = add its key to every block. All other app chrome stays English.
- **Injected `HISTORY` is minimal**: `app-build.md` parses the user's `profile.md` **Focus domains** automatically (no manual value to fill) and does **not** inject blueprint weights or per-domain accuracy — the app owns the constant blueprint and recomputes per-domain accuracy client-side, so nothing stale is shipped in the payload.
- **Cinematic "spatial dark" visual system + theming** (v0.14+ redesign; replaces the warm study-desk look): `<style>` opens with two embedded `@font-face` woff2 (base64, Latin subset) — **Unbounded** (display/numerals) + **Sora** (body); no CDN, stays offline. Tokens live under `:root[data-theme="dark"]` (default) and `:root[data-theme="light"]`; a no-flash inline `<script>` in `<head>` sets `documentElement[data-theme]` from `localStorage("ccaf-theme")` else `prefers-color-scheme`. Topbar **`#themeToggle`** (`setTheme()` persists + swaps ◑/◐; `reRenderCurrentView()` repaints the active view so any computed-color SVG refreshes). Accent = emissive cyan→violet gradient + glow; panels are glass (blur + faint border + soft depth); domain hues re-tuned per theme. **Reduced-motion**: the existing `@media (prefers-reduced-motion:reduce)` reset disables the orb pulse / `.reveal` stagger / button sheen automatically.
- **Dashboard head rebuilt** (`renderDashboard`, replaces the old 4-tile `.tiles` KPI strip): a **"Focus next" coach banner** (`.coach`) — weakest domain (`focus[0]` else lowest accuracy), points under `PASS_PCT`, dominant miss-axis from `computeAxisTally` — whose CTA calls **`startWeakDrill(d)`** (opens `renderConfig()` pre-set to weak mode + that domain + 15 Q). Then a **readiness orb** (`.orb`, conic gradient from `proj`) + three **stat tiles** (`.hero2-chips .statcard`) each with its own glowing micro-viz: `.mini-arc` (accuracy), `.meter` (bank covered), `.spark` (recent mock scores). All gated on the existing empty/`proj==null` fallbacks. `.spark` needs an explicit width (flex bars collapse otherwise).
- **`renderTrend` label fix**: the `PASS_PCT% pass line` label moved to the **left** of the dashed line (was right-anchored and collided with the last point's value label + the line; since the scroll change it is the pinned HTML `.trend-passlbl`); `padR` widened so the rightmost point label never clips. General rule: SVG labels must keep clear space from lines/points/each other.
- **Random mode recent-exam skip** (`recentExamRank()`, constants `RECENT_EXAMS_N=10` / `RECENT_EXAMS_DAYS=14` — the ONE place to tune it; the mode card + config note interpolate both): a question seen in any of the last N exams (recorded + pending) sat within the last D days is skipped; if that leaves fewer than the requested length, the draw tops up from the skipped ones, OLDEST of those exams first. **Random pool segment** (`cfg.fresh`, `#pool`, shown only when Random is selected): `Fresh + top-up · <bank>` = the behaviour above; `Fresh only · <fresh>` makes `poolFor("random", …, {fresh:true})` return ONLY the non-recent questions, so the existing Length cap (`shownAvail`) disables lengths above the fresh count and `All` = fresh count — the same mechanics as Ever failed, no separate logic. The segment is disabled (and `cfg.fresh` reset) when 0 fresh remain; the summary note names the mode. `availByMode(domains, merged, opts)` takes the same `opts`. N=10 / D=14 fits a daily 15/30-question routine with a few skipped days of slack (a 60-question day may drain the fresh pool sooner — that is what the top-up is for).
- **Trend-chart sizing (both `renderTrend` and `domErrTrend`)** — constants `TREND_STEP=44` / `TREND_BASE_W=1000` / `TREND_TICK_MIN=56` + helpers `trendWidth(n, fixed)`, `trendSvgStyle(W)`, `trendTickStep(ticks, plotW)`, `trendScroll(svg, W, pinned)`, `scrollTrendsToEnd(root)`. Root cause this replaced: a fixed 1000-unit width split equally per DATE, so a day with 4 sittings squeezed them (and their score labels) into one cell. Now every sitting is guaranteed `TREND_STEP` units: `W = max(TREND_BASE_W, fixed + n*TREND_STEP)`. Up to the base width the SVG fills the card exactly as before (`width:100%`, no scroll). Beyond it the SVG gets an inline `width:Wpx` (1 unit = 1 px) inside `.trend-scroll.is-scroll` (`overflow-x:auto`), which `renderDashboard` auto-scrolls to the newest sitting (`data-scroll-end`); domain cards render collapsed (a hidden scroller has no `scrollWidth`), so a capturing `toggle` listener re-runs `scrollTrendsToEnd` when a `details.dom-card` opens. Date ticks thin to one per `TREND_TICK_MIN` units of real plot width instead of a fixed ~12. The score labels have no collision logic — the step is the guarantee; if you shrink `TREND_STEP` below an 11px "100" + margin, add one.
